# Lesson guides and exercises

Every lesson is a folder of the repository, `lessons/<NN-slug>/` (for example `lessons/09-todo/`), with two projects in it:

- `exercise/`: the learner's **exercise**, a ready starting project (the state of step 0 of the guide);
- `solution/`: the **solution**, the finished app, which is also the lesson's page on the website.

The lesson page has two tabs: **Guide** (step by step, from the very basics) and **Solution** (the finished app). The
tab bar links to the exercise folder on GitHub; there is no download on the site. Lesson 1 is the reference:
`content/guides/portfolio/` and `lessons/01-portfolio/exercise/`. The lesson folder's README is generated by
`npm run lessons` (`scripts/build-lessons.mjs`): do not edit it by hand.

## The guide: `content/guides/<slug>/hu.md` and `en.md`

Plain Markdown with a few additions. The page header already shows the lesson title, so the file starts with the
introduction. A missing language falls back to the other one.

```md
# What we build                      ← title of the introduction card

Introduction paragraphs…

:::levels
- What the beginner level builds. | about 2 hours
- What the intermediate level adds. | about 3 hours
- What the advanced level adds. | about 3 hours
:::

**Before you start you need:** …

## Beginner level {level=1}         ← level sections: level=1, 2, 3
### Before you start                 ← steps, numbered automatically from 0
Text with `code`, **bold**, [a link](https://…), [[glossary term]] or [[shown text|glossary term]],
and keys like ++Ctrl++ + ++C++. Bold may hold the other marks (**The `ignore` flag.**); nothing else nests.

- list items (an indented line continues the item)

```jsx file=src/App.jsx mark=2,4-6
function App() {
  return <h1>Hello, React!</h1>
}
```                                  ← code: language, optional file name and marked lines

:::check Check                        ← boxes: check, mistake, try, concept (title after the name)
Text of the box.
:::

:::compare                            ← code blocks side by side
```jsx label="Before: a class" file=Hello.jsx
…
```
```jsx label="Today: a function" now file=Hello.jsx
…
```
:::
```

Code languages with colours: `jsx`/`js`, `css`, `shell`. Others (for example `yaml`, `html`) are shown plain.
No raw HTML: the text is rendered as React elements.

### How a guide teaches

- Start from the basics. Say what a new word means the first time it appears, and mark it as a `[[term]]` (the glossary
  will link these).
- One step, one idea. Show the code, explain it in plain words, then tell the learner what they should see
  (`:::check`), what usually goes wrong (`:::mistake`) and something small to try (`:::try`).
- The steps build the app in the exercise project, not in this site's code: plain React, no site helpers.
- Code style by lesson: lessons 1–26 use `function Name() {}` components, 27–50 arrow functions
  (`const Name = () => {}`). Class components appear only in lesson 1's detour.
- Data and pictures the exercise needs come from the exercise itself or from this site (`public/media/…`), never from
  other services.
- Write the Hungarian and the English version with the same steps, the same code structure and the same file, component,
  function and variable names (always English). What the learner types as visible UI text (labels, messages, sample
  content) and as code comments is in the guide's language: Hungarian in `hu.md`, English in `en.md`. Line numbers in
  `mark=` must match the code shown in each file.
- Files that already come with the exercise are shared by both languages, so they are in English; the Hungarian guide
  says so where it matters ("the sample text is in English, feel free to translate it").

## The exercise: `lessons/<NN-slug>/exercise/`

A plain Vite + React project (`package.json`, `vite.config.js`, `index.html`, `src/…`, a bilingual README). Its files are
English and shared by both guides. It is the state of step 0: everything the learner needs to begin, nothing they are
meant to write. Its `package.json` `name` is the folder name the guide suggests for the learner's copy (for example
`todo-list`).

How a learner works with it, and what step 0 of every guide says:

1. Get the repository from GitHub once: `git clone https://github.com/mazsola739/rika-mentoring.git` (or **Code →
   Download ZIP**). Later, `git pull` in that folder brings the new lessons.
2. Copy the lesson's `exercise` folder out of the repository into the learner's own work folder and give the copy the
   suggested name (`lessons/09-todo/exercise` → `todo-list`). The repository copy stays untouched, so `git pull` keeps
   working, and the learner's work is their own project.
3. In the copy: `npm install`, `npm run dev`, then make it a git repository with one commit (`git init`,
   `git add .`, `git commit -m "Starting point"`), so committing each level and `git restore .` work.

Lesson 1 explains all of this in detail (with a file manager and with terminal commands). Later lessons recall it in
a few lines with the commands. To test an exercise without downloading packages: copy the folder into your own scratch
folder, link `node_modules` there to the site's (`New-Item -ItemType Junction -Path node_modules -Target
P:\dev\rika-mentoring\node_modules`), build with the site's Vite, and remove the junction afterwards.

- The exercise is a plain project: it never imports from this site (`@shared/…`). Anything it needs from the site is
  copied in as a small, readable file:
  - **Lessons with an HTTP API** (the Solution uses `shared/mock-api/msw.js`): the exercise runs the same API in the
    browser with Mock Service Worker. Add `msw` to its `package.json` (same version as the site), copy
    `public/mockServiceWorker.js`, put the lesson's handlers and data in `src/mocks/` (from `solution/mocks/`, with
    the helpers they use copied next to them), and start the worker in `src/main.jsx` before rendering. The guide
    explains in a few sentences that this "pretend server" answers `fetch('/api/…')` like a real one, and the learner
    writes the fetch code.
  - **Lessons with the older localStorage back end** (`createMockApi` / `createChannel` from `shared/mock-api/index.js`):
    copy it as `src/fakeApi.js` (English comments) and say in the guide what it pretends to be.
  - **Lessons with an npm library** (for example `qrcode`, `leaflet`): add it to the exercise's `package.json` with the
    site's version.
